About the DfR Browser

Jeri E. Wieringa

2019-01-24 00:00

Source

At the core of the dissertation is a 250 topic model of the periodical literature of the denomination. As I discuss throughout the dissertation, topic modeling is a form of unsupervised machine learning that enables the exploration of a corpus of literature based on the co-occurrence of words, clustered into units called “topics.” While for the computer, the topics represent the likelihood of word occurrences in different contexts, for the human reader the topic can be used to track different themes or discourses within a corpus. And although the model tends to be unstable, in that as a probabilistic representation of the words in a corpus, it will represent the text differently each time the algorithm is run, it provides a useful abstraction of a corpus of literature, a possible interpretation that highlights different features of the collection of texts.

I created the model using a number of computational tools, including the Python library Gensim and MALLET through the command line interface. Topic models are informationally dense representations of a corpus, and as such are most useful for corpus exploration when coupled with some sort of interactive visualization. Such visualizations enable the reader to focus on in particular aspects of the corpus, pointing to further areas for investigation.

For this project, I have used the DfR Browser, created by Andrew Goldstone. While not the only topic model interface available, the DfR Browser has a number of advantages. First, structurally the browser is a static, single-site website, which reduces the complexity of hosting and archiving the work. Second, the browser provides a number of useful interfaces into the topic model data, enabling the reader to see from the level of the overall model and corpus to the level of individual words. Third, the methods used by Goldstone to calculate topic weights over time are similar to those I use throughout the rest of the dissertation, computing the percentage of total tokens each year assigned to each topic. This consistency provides a consistent representation of the topics between the visualizations within the dissertation and the browser, which is vital when moving from the model to interpretation.

To aid in the use of the browser, I provide an overview of the different “view” available within the model browser to help orient the reader and clarify the ways I anticipate the model being used.1 These views are the full model view, the topic level view, the document level view, and the word level view. Each provides a different window onto the tokens within the corpus of Seventh-day Adventist periodical literature and can be used to explore different aspects of the model and of the literature over time.

The Model View

The landing page of the model browser enables the user to view the overall structure of the topic model and provides four different views of all of the topics. The “Grid” view shows all the topics as circles, with the boundary widths indicating overall prominence, while the “Scaled” view (currently not functional) varies the size of the circles according to the prominence of the topic. The “List” view is one of the most productive if interested in change over time. In this view, the topics are listed alphabetically with a miniaturized chart of prevalence over time as well as overall proportion in the corpus, and can be sorted along any of these columns. And finally, the “Stacked” view provides visualization of all of the topics, with band width corresponding to percentage of total words, or word counts, depending on the user selection.

The model level view provides the user insight into the overall structure of the topic model. In these views, we can see that there is a large number of topics for the corpus, with both more generalized and focused topics. Because of the amount of data generated with this many topics, documents, and words, the overall view provides suggestions of places for further inquiry, but offers few clear suggestions of patterns in the overall corpus.

The Topic View

The topic level views allows the user to explore each topic individually in terms of the words that are most prominently associated with the topic, as well as the documents where the highest percentage of tokens is assigned to the topic. Additionally, when a user selects a year in the graph of “conditional probability of words in topic,” the top documents update to reveal the top occurrences of the topic in that year, rather than across all documents. These interface features enable the user to explore which areas of the corpus are most strongly associated with a particular topic.

This information, combined with the graph of topics over time, helps illuminate the patterns in language use identified by the model. I used this information in assigning interpretive labels to the topic, reading the context from the top documents as well as exploring particular years, both with low and high overall prevalence, in order to further refine my understanding of the topics. While the perceived accuracy of the topic assignment decreases with the number of tokens assigned to the topic, for the high prevalence assignments, the view helps illuminate the patterns of language and content captured in the model.2

The Document View

The document level view provides a close view of how the topic modeling algorithm labeled the words within each document, showing each identified topic and the number and percentage of words associated with it. This breakdown of topic assignments provides something of a summary of the content of the document, indicating which general themes or discourses the document is likely engaged with. The view also provides some initial indication as to which topics might be linked to one another.

The document level view can also be used to begin to evaluate the performance of the topic modeling algorithm. In the case of the document linked here, the long list of identified topics, many with only one word associated with it, suggests that the topic model could be further refined by encouraging fewer topic assignments within documents, an aspect controlled through the alpha hyperparameter of the modeling algorithm.3 Despite this weakness, the top three topics assigned to the document provide a good indication of the content of the document, which is a personal testimonial of conversion experience of one of the students at the school.

The Word View

The word level view has two main interfaces: the first shows all of the words that appear in the top 20 for topics and the second shows the topics in which individual words appear. These two interfaces provide insight into the overall language use within the full set of documents, as well as the ways the topic model treated the individual words from the texts. The full list shows the most prominent words that appear in the corpus, providing an unusual but interesting summary of the language of the denomination. The topic view for individual words reveals how words have been grouped with the algorithm, together with the interpretive label I assigned to that cluster of language. This interface provides another way to engage the corpus, working from key words of interest through the associated topics to the documents.

Conclusion

The DfR Browser is well designed to provide users with both a high-level view of a topic model, as well as the more detailed information needed for evaluating the strengths of the model and using the model to identify documents related to a subject of inquiry. The four views of the browser let the users move back and forth between these different views of the corpus and its language, a key feature for putting the model to interpretive work. While not the only topic model browser under development, this approach has significant advantages for research work in humanities contexts, as it grounds the interface in teh documents, rather than the model itself. Additionally, the technical load of the browser is light, simplifying the processes involved in presenting and archiving the model interface.

My dissertation project has also brought to light some additional features that would enhance the browser for model exploration and interpretation. The default set up for the browser enables exploration of the topic model, but not further manipulation of the model data. While the algorithm currently clusters topics based on time, enabling further grouping of documents and topics based on other metadata variables at the level of the user interface would enable additional exploration into the ways particular topics, or discourses are distributed by things such as publication type or geographic region.4 Additional, the inclusion of the document text within the document view, with the topic assignment of the words indicated in some way, would provide further useful information on how the model has characterized the language of the document. Finally, a reporting mechanism that would enable returning a collections of documents that fit a particularly set of parameters would expand the usefulness of the browser from the exploration of a model to leveraging the clustering work of the algorithm to identify related documents on a given topic.

A number of these changes push the interface beyond what can be achieved within a static site, as the memory load on the browser becomes difficult to support. As such, it is also worth considering an adaptation of the browser that relies on a database for serving the corpus and model data. This modification would remove some of the advantages of the static-site approach, but would make the browser a more robust tool for research.

Leveraging a topic model for historical research is a multifaceted problem, extending from the work of the selection and preparation of a set of literature to the interfaces for interpreting and utilizing the resulting data. While experimental work in the digital humanities has focused largely on the process of running the topic modeling algorithm on a set of documents, there is significant research to be done on the pre-processing and post-processing steps that make the running of the algorithm possible and legible. As both of these greatly shape the results of the computational analysis and its usefulness in historical research, they are vital areas for further scholarly attention from scholars working at the intersection of computation and the humanities.
